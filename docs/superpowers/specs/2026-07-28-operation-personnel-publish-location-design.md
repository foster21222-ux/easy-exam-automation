# 人员任务发布位置恢复设计

日期：2026-07-28
状态：方案 A 已确认

## 目标

首次发送人员任务时，如果运控批次尚未发布，系统必须在读取考试日程后重新精确打开当前批次详情，完成发布并回读“已发布”状态，然后才继续人员任务配置与发送。

## 根因

未发布批次的人员任务预检会切换到“考试 → 易考”页面读取真实考试日程。后续 `publish_batch` 检查点直接在当前页面查找“发布”按钮，没有重新建立批次详情页面位置，因而可能得到“发布按钮实际 0 个”并阻断。

## 已确认方案

采用方案 A：

1. 保留未发布预检读取考试日程的现有行为。
2. `publish_batch` 检查点发现当前批次未发布时，根据本次指令中的批次代码重新精确定位并打开该批次详情。
3. 只有重新定位成功后才查找唯一可见的“发布”按钮。
4. 点击发布并完成运控确认弹窗。
5. 回读批次状态；只有状态为“已发布”才继续后续人员任务检查点。
6. 批次已经发布时不重复点击发布。

不扩大“发布”文字选择器，不使用模糊匹配，也不缓存并复用可能失效的详情地址。

## 安全边界

- 重新定位必须按批次代码精确匹配，不允许打开名称相似的其他批次。
- 重新定位、发布按钮或状态回读任一步骤失败时立即阻断，不打开人员任务单、不选择收件人、不发送。
- 不改变考试日程读取、人员参数同步、固定收件人和运控内置发送机制。
- 未经用户单独确认，不执行真实人员任务发送验证。

## 验收标准

1. 回归测试复现：未发布预检停留在考试日程页时，旧流程直接发布会失败。
2. 修复后事件顺序为：读取日程页、重新定位批次详情、点击发布、打开任务单。
3. 发布后回读仍为未发布时阻断。
4. 已发布批次不执行重新定位发布动作。
5. 人员任务执行器聚焦测试、全量 Node 测试和 Python 测试通过。
6. 代码同步至 Application Support 运行时，8765 健康检查通过。

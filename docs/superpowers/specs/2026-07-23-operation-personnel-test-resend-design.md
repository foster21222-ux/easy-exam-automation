# 运控人员任务单测试环境重发接管设计

## 目标

在不放宽生产校验、不伪造本地成功状态的前提下，让测试环境能够：

1. 忽略泛微业务需求单与运控测试项目之间不可修改的项目编码、项目名称差异。
2. 从运控可见页面确认已经存在的首次发送记录。
3. 将当前运控配置和任务单快照作为外部首次发送基线。
4. 仅在内容确有变化并填写变化摘要后，执行运控内置的再次发送流程。

本次只验收再次发送。首次发送、首次自动发布和完整全流程留待新建测试项目后验证。

## 环境边界

### 测试环境

批次详情身份校验忽略：

- 项目编码；
- 项目名称。

仍严格校验：

- 批次代码；
- 批次名称；
- 项目部归属；
- 项目经理；
- 系统类型。

### 生产环境

项目编码、项目名称和其它批次身份字段全部严格校验，不应用任何测试例外。

环境只能由服务端 `OPERATION_CONSOLE_ENVIRONMENT` 决定。请求体和页面不能切换或伪造环境。

## 外部首次发送基线

当平台没有 `lastSuccessfulFingerprint`，但运控可见页面存在发送记录时：

1. 必须精确读取至少一条运控发送记录。
2. 必须完成批次、日程、人员配置、日期、考务需求、任务单和收件目录的完整只读快照。
3. 将该快照作为本次预览的外部首次发送基线。
4. 将预览模式标记为 `resend`，但不写入或伪造 `lastSuccessfulFingerprint`。
5. 在预览令牌中记录模式和基线快照指纹，发送时必须重新校验。
6. 记录审计事件，表明重发基线来自运控可见的既有发送记录。

没有可见发送记录时仍按首次发送处理，不允许请求参数强制切换为重发。

## 重发门槛

外部基线接管后，必须同时满足以下条件才能再次发送：

- 当前目标内容与外部基线存在至少一项真实变化；
- 用户填写非空变化摘要；
- 运控当前状态与预览基线一致，没有独立人工漂移；
- 发送条件全部满足；
- 测试收件人精确匹配“演示组 / 张乐翔”，无抄送；
- 最终发送前完成一次合并二次确认。

内容完全一致时禁止重发。不得为了测试而制造或伪造变化记录；变化必须来自平台允许编辑的字段，并同步修改运控相应配置。

## 状态与数据

新增的预览态信息仅保存完成重发所需的最小数据：

- `kind: "resend"`；
- 外部基线快照；
- 外部基线快照指纹；
- 触发接管的可见发送记录摘要；
- 审计事件。

不保存运控凭据、完整人员目录或隐藏接口数据。

只有再次发送成功且出现本次 attempt 之后的新运控发送记录，才能正常写入：

- `lastSuccessfulFingerprint`；
- `lastOperationSnapshot`；
- `sendHistory`。

## 安全失败

以下情况必须阻断且不点击发送：

- 生产环境存在任何批次身份不一致；
- 测试环境中除项目编码、项目名称以外的身份字段不一致；
- 运控发送记录不可见、缺失或结构不唯一；
- 外部基线快照不完整；
- 内容没有变化；
- 变化摘要为空；
- 预览后运控状态发生变化；
- 收件人不唯一或不符合测试规则。

最终发送按钮只能点击一次。发送记录两阶段核验失败时进入 `result_unknown`，不能自动重试。

## 测试与验收

自动测试至少覆盖：

1. 测试环境忽略项目编码和项目名称。
2. 测试环境仍阻断批次名称或其它身份字段不一致。
3. 生产环境仍阻断项目编码和项目名称不一致。
4. 无本地成功状态但存在运控发送记录时进入重发预览。
5. 没有可见发送记录时不接管重发。
6. 外部基线模式下内容不变禁止发送。
7. 外部基线模式下变化摘要必填。
8. 预览基线指纹变化时发送阻断。
9. 新发送记录出现后才写入本地成功状态。

真实测试环境验收：

- 当前批次只执行再次发送；
- 最终点击前展示完整合并确认并取得用户即时确认；
- 成功后核对右上角新增“再次发送”记录；
- 不把本次结果视为首次发送全流程验收。

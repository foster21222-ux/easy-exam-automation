# 运控批次可见日程表兼容修复设计

## 问题

人员任务首次检查会先从未发布批次的可见详情页读取考试日程。当前运控页面使用以下表头：

- 日程代码
- 日程
- 时长(分钟)
- 考试名称
- 考生提前登录(分钟)

现有读取器要求“开始时间”列，并读取“科目名称”“时长”“提前登录分钟数”，因此将真实存在的日程表误判为不可见并阻断人员任务。

## 设计

只修改运控批次详情页的只读日程解析：

1. 保留“日程代码”作为唯一日程表识别依据之一。
2. 同时接受当前的组合“日程”列和原有的“开始时间/结束时间”列。
3. 组合“日程”列按页面中的时间范围拆分为开始时间和结束时间。
4. 将“考试名称/科目名称”“时长(分钟)/时长”“考生提前登录(分钟)/提前登录分钟数”分别规范化为现有内部字段。
5. 表格缺失、表头不完整、日程范围无法拆分时继续阻断，不猜测数据。

人员任务单弹窗、批次写入、发布、收件人选择和发送流程不在本次修改范围内。

## 实机补充：详情页签与快照刷新

批次详情默认页签不展示考试日程。未发布批次首次检查必须先复用批次修改模块的只读导航，进入“考试 → 易考”，再读取日程表。切换页签后必须清除切换前的可见页面快照，防止继续使用默认页签中“不存在日程表”的缓存结果。

此导航只读取页面，不发布批次、不修改日程，也不触发人员任务发送。

## 验证

先增加当前运控真实表头的回归测试并确认旧代码失败，再实施最小兼容修改。验证范围包括：

- 当前组合“日程”列可生成正确的开始、结束时间及其他日程字段；
- 原有分列格式保持兼容；
- 不完整或歧义格式仍被阻断；
- 未发布批次先进入考试日程页签，并在切换后重新读取可见页面；
- 人员任务相关测试和项目全量测试通过。

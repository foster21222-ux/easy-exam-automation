# 运控人员任务统一草稿设计

## 目标

修复人员任务发送成功后，配置台查询状态时重新套用默认值，导致已确认草稿、最近成功版本和运控实际值出现虚假差异的问题。

## 来源边界

人员任务数据分为四层：

1. 来源数据：泛微业务需求、易考需求单、运控批次创建结果和环境固定规则。
2. 已确认人工配置：人员落实开始日期、人员落实结束日期、人员名单提交日期、监考比例和监考人数。
3. 最近成功发送版本：用户确认并实际发送的完整目标。
4. 运控实际快照：自动化从运控可见页面回读的实际配置和发送记录。

考试日程和场次变化只能来自易考需求单。运控日程只提供日程代码和同步结果，用于核验，不得作为新的业务需求来源。项目中的其他考试场次数据不得独立触发人员任务日程变化。

## 字段所有权

| 字段 | 首次来源 | 后续来源 |
| --- | --- | --- |
| 批次代码、批次名称 | 运控批次创建结果 | 当前项目的运控批次结果 |
| 考试日程、考试名称、最早登录时间 | 易考需求单 | 最新已确认的易考需求单 |
| 日程代码 | 运控批次日程回读 | 运控批次日程回读 |
| 人员落实开始、结束、名单提交日期 | 规则建议后由用户确认 | 最近一次用户确认值 |
| 监考比例、监考人数 | 规则建议后由用户确认 | 最近一次用户确认值 |
| 考生计算基数 | 现有考生基数规则 | 按现有考生基数规则重新读取；变化时触发复核，但不得直接覆盖已确认人数 |
| 人员平台、服务类型、登录监控 | 固定规则 | 当前固定规则 |
| 收件人、抄送人 | 当前环境固定规则 | 当前环境固定规则 |
| 运控实际值、发送记录 | 运控可见页面 | 只用于校验和审计 |

## 统一当前目标草稿

系统只允许一个用于展示、比较和发送的“当前目标草稿”：

1. 从来源数据生成来源控制字段。
2. 首次发送且没有人工确认值时，填入日期、比例和人数的默认建议。
3. 已有人工确认值时，将人工确认值合并到来源草稿。
4. 加入批次受管日程和运控日程代码。
5. 生成当前目标指纹。

项目卡片、人员任务详情、预览和发送必须调用同一套合并逻辑，不能分别生成草稿。

默认建议只在首次初始化时生效。查询日期变化不得重新生成“人员落实开始日期”，查询也不得把比例恢复为 `1:50` 或重新覆盖监考人数。

## 首次发送

1. 生成当前目标草稿。
2. 读取运控实际状态，确认批次身份和日程。
3. 在配置台统一展示目标值、运控修改前后、日程和固定收件人。
4. 用户调整可编辑字段并确认。
5. 原子保存人工确认字段和本次发送目标，创建发送尝试。
6. 运控未发布时先发布；核验日程；更新人员配置、日期和考务需求。
7. 通过运控内置机制发送任务单。
8. 回读本次新发送记录。
9. 发送成功后保存当前目标草稿、人工确认字段、成功指纹、运控实际快照和发送历史。

## 需求更新与再次发送

1. 泛微或易考需求发生变化后，重新生成来源控制字段。
2. 易考需求单变化可更新考试日程、考试名称和最早登录时间；不存在独立的考试场次变更源。考生计算基数不属于日程或场次来源，继续使用现有计算规则。
3. 保留最近一次确认的日期、比例和人数。
4. 将当前目标草稿与最近成功发送版本比较。
5. 完全相同时保持“已发送”，不允许重发。
6. 有实质变化时显示“有变更待处理”。
7. 预览时读取运控实际状态，并与最近成功运控快照比较；不一致则阻断人工处理。
8. 用户确认修改内容和变化摘要后，更新运控并再次发送。
9. 回读“再次发送”记录后，用新版本替换最近成功发送版本。

## 用户主动调整并再次发送

人员任务已发送且泛微、易考需求均未变化时，配置台仍提供“调整人员任务并重新发送”入口。

1. 入口以最近成功发送版本为基线，不重新套用首次默认值。
2. 用户只能调整人员落实开始日期、人员落实结束日期、人员名单提交日期、监考比例和监考人数。
3. 考试日程、考试名称和最早登录时间继续只读，并且只能来自易考需求单。
4. 提交前读取运控实际状态，并与最近成功运控快照比较；不一致时阻断人工处理。
5. 修改后的当前目标与最近成功发送版本完全相同时，阻断并提示“内容未变化，不允许重复发送”。
6. 存在实质变化时，展示修改前后、固定收件人和变化摘要，用户二次确认后同步修改运控并再次发送。
7. 回读“再次发送”记录后，保存新的人工确认字段、当前目标草稿、成功指纹、运控实际快照和发送历史。

## 发送结果和恢复

- 发送动作前失败：保留可恢复状态，不更新最近成功版本。
- 已进入发送动作但未看到记录：状态为“结果未知”，不得再次点击发送。
- 只读补查找到记录：保存原发送目标、成功指纹、运控快照和发送历史。
- 只读补查未找到记录：继续保持“结果未知”。
- 运控被人工改成与最近成功快照不一致时：阻断，不自动吸收到需求草稿。

## 查询和页面刷新

发送完成后，页面继续自动轮询。终态出现后重新查询人员任务状态：

- 查询返回统一当前目标草稿，不得用新生成的默认草稿覆盖已确认人工配置。
- 当前目标指纹等于最近成功指纹时显示“内容未变化，不允许重复发送”。
- 只有来源字段、固定规则或人工确认字段发生实质变化时才显示“有变更待处理”。

## 兼容范围

历史状态缺少独立人工确认字段时：

1. 优先从最近成功发送目标恢复。
2. 其次从持久化草稿恢复。
3. 两者均不存在时才使用首次默认建议。

不迁移或修复与当前项目管理流程无关的旧导入入口。

## 验收标准

1. 用户发送 `1:55 / 70人` 后，重新查询仍显示 `1:55 / 70人`，状态为已发送。
2. 第二天打开同一项目，开始日期不因当天日期变化而改变。
3. 易考需求单日程变化时显示有变更，但保留已确认日期、比例和人数。
4. 运控日程变化不能反向成为业务需求变化，只能触发一致性阻断。
5. 完全相同内容不能重发。
6. 再次发送成功后，项目卡片、详情、成功快照和发送历史使用同一版本。
7. 结果未知补查成功后，不产生第二次发送并恢复成功状态。
8. 来源需求未变化时，可通过“调整人员任务并重新发送”修改人员日期、比例和人数；未修改任何值时仍禁止重发。
